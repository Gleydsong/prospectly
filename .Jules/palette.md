## 2023-10-13 - [Safely merging ARIA attributes and sanitizing useId() in form controls]
**Learning:** When building reusable UI form controls (Input, Textarea, Select) that spread `{...props}` to the underlying element, internal ARIA attributes (like `aria-describedby` or `aria-invalid`) placed before `{...props}` can be inadvertently overwritten by the consumer if they aren't safely merged. Furthermore, when generating an automatic ID using React's `useId()` and sanitizing it (e.g., removing colons with `.replace(/:/g, '')` to avoid CSS selector issues), it's crucial to apply the sanitization *only* to the auto-generated ID. Applying it to a user-provided `id` or `name` property can lead to unexpected mutations that break form submission, labeling, or test selectors.
**Action:** Always compute a safe, combined value for ARIA attributes (e.g., joining internal `error ? errorId : undefined` with `props['aria-describedby']`), and apply these specific ARIA attributes explicitly *after* spreading `{...props}` onto the element. In addition, when implementing fallback ID generation, sanitize `useId()` immediately upon calling it (e.g., `const autoId = useId().replace(/:/g, '')`), rather than applying the sanitization to the final resolved ID (which might be user-provided).
