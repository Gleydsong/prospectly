## 2024-10-04 - Safely merging internal ARIA attributes
**Learning:** When building reusable UI components (like Input, Select, Textarea), internally managed ARIA attributes (such as `aria-invalid` or `aria-describedby` linked to an inline error message) must be applied *after* spreading `{...props}` to prevent them from being inadvertently overwritten by the consumer.
**Action:** When spreading props on primitive elements, always ensure critical internal ARIA attributes are placed after `{...props}`. For attributes like `aria-describedby`, safely merge the internal reference (e.g., to an error ID) with any consumer-provided reference (e.g., `props['aria-describedby']`). Additionally, always sanitize `useId()` output (e.g., `.replace(/:/g, '')`) to prevent CSS selector issues when used as an ID.
