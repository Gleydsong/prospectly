Três riscos prioritários
  1. Access + refresh tokens em localStorage (XSS futura = sessão roubada).
  2. ADMIN pode promover membro (incl. a si) a OWNER.
  3. CSP ausente/quebrada em produção + Swagger sempre público + deps high no audit.

O backend já aplica JWT global, isolamento por organizationId, Argon2, ValidationPipe estrito e Stripe com assinatura + Price IDs no servidor. Os maiores gaps estão na sessão no browser, RBAC fino e hardening HTTP/CI.

4. Detalhamento dos achados

SEC-001 — Tokens JWT em localStorage Alto

Status: Confirmada · OWASP/CWE: A07 / CWE-922

Arquivo: apps/web/src/stores/auth.store.ts

Access + refresh + user persistidos via Zustand persist. XSS lê refresh de longa duração.

Correção (Fase 3): refresh em cookie HttpOnly/Secure/SameSite; access em memória; CSRF nas mutações.

SEC-002 — Escalação ADMIN → OWNER Alto

Status: Confirmada · OWASP/CWE: A01 / CWE-269

Arquivos: organizations.service.ts, update-member-role.dto.ts, controller

Invite bloqueia OWNER; update aceita qualquer Role. ADMIN no @Roles pode promover.

Correção (Fase 1): só OWNER atribui OWNER (ou fluxo de transferência dedicado); testes 403.

SEC-003 — CSP inadequada / ausente Alto

Status: Confirmada · A05 / CWE-693

Meta CSP no Vite com connect-src só localhost; nginx sem CSP; landing sem headers.

Correção (Fase 2): CSP em nginx + next.config.ts headers().

SEC-004 — Dependências high + CI soft-fail Alto

Status: Confirmada · A06

pnpm audit --audit-level=high || true não bloqueia o pipeline.

Correção (Fase 2/4): remover soft-fail; patch runtime primeiro; exceptions documentadas.

SEC-005 — Refresh sem family revocation Médio

Token revogado falha, mas reuse após rotação não mata a família.

Correção (Fase 1): se refresh já revogado com replacedById → logoutAll(userId).

SEC-006 — Sem throttle em refresh/reset Médio

Correção (Fase 1): @Throttle dedicado nesses endpoints.

SEC-007 — Enumeração de e-mail no register Médio

ConflictException('Email already registered') vs login genérico.

Correção (Fase 1): resposta uniforme ou delay constante.

SEC-008 — Webhook Stripe sem idempotência Médio

Signature OK; falta persistir event.id.

Correção (Fase 2): tabela/unique + skip se já processado.

SEC-009 — Swagger sempre público Médio

Correção (Fase 1): montar /api/docs só fora de production.

SEC-010 a SEC-013 Médios

  • SEC-010 — getCurrent expõe Stripe IDs → select mínimo (Fase 2).
  • SEC-011 — href={lead.website} → allowlist http(s) (Fase 2).
  • SEC-012 — location.assign → allowlist hosts Stripe (Fase 2).
  • SEC-013 — compose ports/defaults → documentar + defaults seguros (Fase 2).

SEC-014 a SEC-019 Baixos

  • SEC-014 — não logar reset token
  • SEC-015 — JWT secret min ≥ 32
  • SEC-016 — validar from no login
  • SEC-017 — emailVerified (Fase 3)
  • SEC-018 — redact password/refreshToken no Pino
  • SEC-019 — headers na landing
