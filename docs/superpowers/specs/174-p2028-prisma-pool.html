Spec #174 — Isolar pool Prisma (P2028)

Relatórios e outbox deixam de esgotar o pool da API HTTP. Pico → Relatórios 503, login e ficha continuam.

Issue #174 Branch feat/p2028-prisma-pool Sem réplica / sem cubo

O que foi feito

Problema: Relatórios (R4) e o worker de OutboxEvent partilhavam um pool Prisma sem teto. Sob carga o Postgres recusava conexões (P2028) e derrubava login/ficha junto com a agregação.

  • API HTTP: connection_limit=5, pool_timeout=10s (não sobrescreve params já na URL).
  • Worker: connection_limit=3 — menor que a API, para outbox não matar HTTP.
  • Outbox processor: concorrência 2 (< pool 3), invariante testada.
  • Relatórios: SET LOCAL statement_timeout = 8s + maxWait 5s. P2028/P2024/timeout → 503 REPORTS_QUERY_TIMEOUT, copy «Relatórios indisponível. Tente de novo.» Sem retry interno.
  • P2028 continua métrica de transação inesperada (o 503 é lançado fora da $transaction).
  • UI Relatórios: copy recuperável + botão «Tentar novamente» (ação do utilizador, não loop).

Wizard depois do merge: confirmar max_connections do Postgres no Render. Não inventar credenciais.
