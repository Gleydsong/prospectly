# Plano de implementação i18n do App (PT/EN)

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: Use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa a tarefa. Passos usam sintaxe de checkbox (`- [ ]`) para rastreamento.

**Objetivo:** Persistir locale do usuário (`pt`/`en`) no register e settings, e renderizar a UI do web app nesse idioma via i18next.

**Arquitetura:** Prisma `User.locale` + DTOs Nest auth/users expõem; app Vite inicializa i18next, detecta locale do browser no register, sincroniza idioma de `AuthUser.locale`, e armazena copy em `pt.json` / `en.json`.

**Stack:** Prisma, NestJS, Zod/class-validator, React, i18next, react-i18next, Vitest, Jest

## Restrições globais

- Locales apenas: `pt`, `en`
- Default no register a partir do browser: `pt*` → `pt`, senão `en`
- Alterar locale em Settings via `PATCH /users/me`
- Locale de data: `pt`→`pt-PT`, `en`→`en-GB`
- Não traduzir landing ou e-mails neste plano
- Preferir padrões existentes em `apps/api` e `apps/web`

- [ ] **Passo 2: Helpers**

```ts
export type AppLocale = 'pt' | 'en';

export function detectBrowserLocale(lang = typeof navigator !== 'undefined' ? navigator.language : 'en'): AppLocale {
  return lang.toLowerCase().startsWith('pt') ? 'pt' : 'en';
}

export function toIntlLocale(locale: AppLocale): string {
  return locale === 'pt' ? 'pt-PT' : 'en-GB';
}
```
