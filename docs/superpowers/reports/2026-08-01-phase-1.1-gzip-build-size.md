# Phase 1.1 — gzip build size note

Date: 2026-08-01  
Branch: `codex/1.1-lazy-routes-error-boundary`

## Change

- `apps/web`: `React.lazy`/`Suspense` for dashboard, imports, settings and billing routes; `AppErrorBoundary` + optional Sentry stub (`VITE_SENTRY_DSN`).
- `apps/landing`: Three.js globe deferred until visibility + idle; static PNG fallback for reduced-motion / no WebGL.

## Measurement (after)

`pnpm --filter @prospectly/web build` (Vite 6.4.3):

| Asset | gzip |
| --- | ---: |
| `index` (entry JS) | 171.15 kB |
| `dashboard-page` (lazy, includes Recharts) | 111.02 kB |
| `settings-page` (lazy) | 6.00 kB |
| `imports-page` (lazy) | 3.81 kB |
| `pix-checkout-page` (lazy) | 1.12 kB |
| `settings-privacy-page` (lazy) | 0.90 kB |
| `billing-result-page` (lazy) | 0.65 kB |
| CSS | 5.57 kB |

## Interpretation

Before this change, dashboard (+ Recharts ~111 kB gzip) shipped on the critical path with the entry bundle. After lazy routes, first paint JS is the entry (~171 kB gzip); heavy dashboard code loads only when navigating to `/`. Settings, imports and billing follow the same pattern.

Landing: Three.js is no longer required for first paint of the conversion band — static `/globe/earth-reference.png` is shown until visibility + idle (or permanently under reduced-motion / no WebGL).
