# Landing Art Direction

Create a visual system before writing components. Make the business, its real imagery, and the conversion goal determine the page; do not apply a generic SaaS skin.

## Workflow

1. Extract only verified inputs: brand, audience, offer, CTA, location, photos, proof, and constraints. Omit unknown facts rather than inventing them.
2. Choose one visual direction and state it in five tokens: mood, contrast, type character, image treatment, and surface treatment. Do not mix unrelated aesthetics.
3. Compose a conversion narrative: promise, credibility, offer/process, proof, friction-reduced CTA, contact.
4. Build mobile-first. Establish the 320–480px layout first, then enhance at 768px and 1024px; do not merely shrink desktop columns.
5. Validate hierarchy, contrast, focus, touch targets, empty states, image crop behavior, and the primary CTA at every breakpoint.

## Composition rules

- Prefer one dominant hero image or product visual, a precise `h1`, one primary CTA, and one lower-commitment secondary action.
- Use a restrained type scale, 2–3 surface levels, a small spacing scale, and at most one signature visual device per page.
- Put real photos in meaningful layouts: editorial bleed, split composition, gallery sequence, or service proof. Do not repeat the same image decoratively.
- Use cards only when they group comparable choices. Avoid a grid of equal generic boxes.
- Keep copy scannable: eyebrow, outcome-led heading, supporting line, action. Make legal/privacy copy quiet but readable.
- Preserve semantic landmarks, heading order, visible focus, 44px minimum touch targets, descriptive alt text, and 4.5:1 text contrast.

## Output contract

For a generated page, provide a small art-direction summary internally before code: selected direction, audience, primary CTA, section order, responsive behavior, and motion intent. The final artifact must contain only the target format requested by the host.

Read [references/design-system.md](references/design-system.md) when selecting a direction, structuring responsive sections, or auditing a finished page.
